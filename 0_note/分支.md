# Git 分支 笔记版（命令 + 场景 + 问题+解决）

> 约定：主分支 `master`（稳定、上线用）；开发分支 `dev`；功能分支 `feat/xxx`；bug分支 `fix/xxx`

## 一、基础分支命令

```bash
# 1. 查看所有分支（* 代表当前所在分支）
git branch

# 2. 新建分支（只是创建，不切换过去）
git branch dev

# 3. 创建并直接切换到新分支（最常用）
git switch -c dev
# 老写法：git checkout -b dev

# 4. 切换已有分支
git switch master
# 老写法：git checkout master

# 5. 删除本地分支（分支已经合并完才能删）
git branch -d dev
# 强制删除（没合并，确定不要了才用）
git branch -D dev

# 6. 查看远程分支
git branch -r

# 7. 把本地分支推送到远程（第一次推送新分支）
git push -u origin dev

# 8. 合并分支：把dev合并进master（先切到master再合并）
git switch master
git merge dev
```

## 二、常用场景 + 会遇到的问题 + 解决

### 场景1：新开分支做一个新功能（最常用）

流程：

```bash
# 保证master是最新
git switch master
git pull origin master
# 新建功能分支
git switch -c feat/demo
# 写代码 → add → commit
# 写完推远程
git push -u origin feat/demo
```

✅ 作用：功能开发不污染master，做完再合并。

❗ 问题：切分支的时候，有未提交改动，切分支报错

> `error: Your local changes to the following files would be overwritten...`
> ✅ 解决：

```bash
# 方案A：先提交
git add .
git commit -m "xxx"
# 方案B：暂时存起来（推荐，没写完不想提交）
git stash
# 切完分支回来再恢复
git stash pop
```

---

### 场景2：功能写完，合并到dev测试

流程：

```bash
git switch dev
git pull origin dev
git merge feat/demo
git push origin dev
```

❗ 问题：合并冲突（同一个文件同一行两边都改了）
提示 `Automatic merge failed; fix conflicts and then commit the result.`
✅ 解决：

1. 打开文件，找到 `<<<<<<< HEAD`、`=======`、`>>>>>>> 分支名`
2. 手动删掉标记，保留你想要的代码
3. 保存文件
4. `git add .`
5. `git commit`（vim直接:wq）
6. 再push

> 笔记：冲突只会出现在**同一个路径的同一个文件**

---

### 场景3：master上紧急修bug，正在dev写一半

流程：

```bash
# dev里代码写一半，先暂存
git stash
# 切master，拉最新
git switch master
git pull origin master
# 新建bug分支修复
git switch -c fix/bug01
# 修改bug → add → commit → push
# 修复完合并回master
git switch master
git merge fix/bug01
git push origin master
# 切回dev，恢复之前写一半的代码
git switch dev
git stash pop
```

❗ 问题：stash pop之后，出现冲突
✅ 解决：和合并冲突一样，手动改文件，add，commit

---

### 场景4：删除已经合并完的功能分支

```bash
# 删除本地
git branch -d feat/demo
# 删除远程分支
git push origin --delete feat/demo
```

❗ 问题：`git branch -d 分支名` 报错，提示没合并
✅ 解决：确认这个分支代码不要了，用强制删除

```bash
git branch -D feat/demo
```

---

### 场景5：拉取别人新建的远程分支到本地

别人建了 `feat/xxx` 推到github，你本地看不到

```bash
# 更新远程分支信息
git fetch origin
# 切换到这个远程分支，自动创建本地对应分支
git switch feat/xxx
```

❗ 问题：git branch看不到远程新分支
✅ 解决：先 `git fetch origin`，同步远程信息

---

### 场景6：合并错了，想撤销本次合并

刚在master合并了dev，还没push

```bash
# 回退到合并之前的commit hash
git reset --hard 合并前哈希
```

⚠️ 危险：--hard 会丢掉本地改动！

## 三、容易踩坑的重点总结（写笔记）

1. **不要带着未提交的代码随便切分支**，优先 `git stash`
2. 合并前，先切到目标分支，`pull` 拉最新，减少冲突
3. `-d` 安全删除分支；`-D` 强制删除，谨慎
4. 冲突本质：同一个文件同一位置两边修改不一样，Git不知道用哪个
5. `git switch` 是新版推荐；`checkout` 老命令，既能切分支又能撤销文件，容易混淆
6. 多人协作：**master尽量不要直接在上面写代码**，全部走分支合并
